# Generalization plan and limits

H5Reclaim tries to recover measurements that remain physically present in damaged HDF5 storage, assign them only to coordinates justified by surviving evidence, and mark everything else unknown. This document records what version 0.9 implements and the remaining engineering and evaluation work. The [current status](status.md), [usage guide](usage.md), and [damage taxonomy](damage-taxonomy.md) describe the routes and their narrower conditions.

## What works in version 0.9

The guided rescue command selects one dataset and publishes a separate derived HDF5 file with an evidence report and validity or status map. The chunked structural route supports selected older and newer superblocks, object headers, groups and hard-link paths. It follows intact deeper version-1 B-trees and can bridge **one missing leaf link** only when a unique two-sided sibling chain and the parent's exact interval agree. It validates intact single-chunk, implicit, fixed-array, extensible-array (including bounded paged blocks), and version-2 B-tree modern indexes. Selected one-pointer damage in fixed-array, extensible-array, and version-2 B-tree nodes can be addressed when exactly one bounded candidate restores the **original stored parent checksum**, independently checked child evidence and complete traversal, and passes extent, coordinate and ownership checks. Other missing modern links and free-floating orphans are not assigned. Bounded fallback can resolve selected older symbol-table, modern compact, and dense-group paths when native metadata open fails. It covers older rank-one through four numeric/filter layouts and bounded header continuations. Selected checksummed v2 committed datatypes and SOHM list or type-7 v2 B-tree leaf/one-internal-level managed-heap shared dataspace, datatype, and filter messages are supported; other encodings remain unsupported. Observed allocations of other rooted local datasets and contradictory rooted link counts can disqualify a proposal. An incomplete inventory is not proof that no competitor exists.

Structural chunked values are rank-one through rank-four canonical fixed-width integers or IEEE float32/64 and selected self-contained fixed-size compound, enum, array, fixed string and opaque records. The latter retain their exact HDF5 encoded datatype and raw record bytes instead of being converted into a familiar numeric type. Supported built-in shuffle, DEFLATE, and Fletcher32 pipelines are reversed in declared order with per-chunk skip masks. The route handles edge chunks, growth, and sparse slots within limits. The evidence ledger records anchors, index paths, coordinates, byte extents, hashes, filter checks, and contradictions. An accepted unchecksummed chunk is structurally located, but its current bits are not independently proven to be the pre-damage measurement. Missing, ambiguous, undecodable, and unsupported regions remain distinct; anchored undecodable raw extents can be exported as **unassigned** fragments. Variable-length, heap and reference graphs are not structural fixed-record types.

A separate rooted structural route accepts selected compact and contiguous numeric datasets, rank zero through four, with layout messages v3–v5. It retains only complete elements from a physically truncated contiguous tail and marks incomplete or absent elements unknown. It uses a surviving hard-link path, datatype, dataspace, layout, and address; it does not search the file for plausible numbers. A bounded rooted hard-link census rejects a selected object whose observed aliases contradict its declared count, including a redirected older native link that would otherwise yield another dataset's values. Traversal that exceeds its group, link or time bounds refuses. The older unchecksummed metadata route still has a weaker historical ownership guarantee than a checked modern header: coordinated edits to links and declared counts can appear consistent. A positively observed competing rooted allocation causes refusal.

For physical tail cuts through **chunked** datasets, an explicit route allows
private snapshot padding only to let bounded raw parsers see declarations
still present in the original bytes. Its declaration may exceed actual EOF
by at most 256 MiB. All selected metadata and index bytes, and each accepted
stored chunk, must lie inside actual physical EOF. Cut indexed payloads are
unavailable; a cut selected path or index refuses. Private zeros are never
measurements.

Two single-byte modern metadata trials target only a superblock root pointer
or a selected layout's modern chunk-index pointer. They search substitutions
against the original checksum, require a unique match, then check rooted
metadata, complete selected index, native selected-open and owner conflicts
on a disposable copy. Only derived selected current values are published.
Multiple changed bytes, an altered checksum field, an unsupported parent,
or a forged but self-consistent historical acquisition cannot be repaired
or authenticated by this trial.

Related-file routes use explicit manifests, pinned hashes, private snapshots, and checked physical extents. External raw export maps complete elements through declared segments; it refuses an unverified supplied file and marks physically absent element bytes unknown. Finite virtual datasets map supported ALL or regular hyperslab selections to supplied local native-readable numeric sources. Missing VDS sources and unallocated source coordinates remain unknown, even where native HDF5 would show fill. One selected external link can cross to an explicitly pinned HDF5 target whose selected dataset is reached only by local hard links; target offsets are attributed to that target. Family and two-member Split driver routes validate their supplied member layout before native-readable export. These routes materialize a local selected dataset and do not reproduce the original cross-file configuration.

The capture-baseline, capture-element-baseline, capture-capsule, and optional capture-parity/capture-erasure commands are **prospective** tools to run while an acquisition is intact. Prior hashes can gate current decoded chunks by coordinate, or stored compact/contiguous numeric elements, withholding payloads that changed even when their format has no checksum. Pinned independent HDF5 replicas can supply matching chunks later. The XOR parity sidecar can reconstruct exactly one unknown chunk per stripe. The GF(256) sidecar retains two to four parity shards and can reconstruct up to that many unknown nominal chunks per stripe, provided all surviving companions and reconstructed results match independently pinned prior coordinate hashes. These redundancy routes require surviving selected metadata and index. Hash comparison alone cannot reconstruct an unmatched byte, and a baseline captured after damage is not trustworthy prior evidence.

A separately retained capsule records the exact selected HDF5 schema
template, pre-incident physical chunk map, raw and decoded hashes and, for
unfiltered data, smaller block hashes. It carries no measurement bytes. The
capsule route can use surviving raw bytes even when a damaged root, selected
header or index prevents ordinary HDF5 access. It accepts only whole raw
chunks or matching unfiltered blocks at captured offsets, marks missing or
changed values unknown, and requires the capsule's independently retained
SHA-256. The source must be a bounded local chunked dataset at capture, with
no more than 512 MiB logical data and 8,192 chunk-grid positions. A capsule
does not prove capture timing, support moved payloads, decode a broken
filtered stream, or recreate destroyed unique bytes.

The explicit version-3 status trial requires a valid original superblock checksum, write flag without reserved bits, and end-of-address inside the physical file. It clears only flag and checksum on a disposable copy before bounded native-readable export. A successful trial cannot establish when corruption happened or whether an interrupted acquisition finished. The separate optional `probe-status` command uses `h5clear` on a disposable copy when available; neither route is general metadata repair.

The native-readable route is separately labeled: it copies values that the linked HDF5 library can currently read. It supports bounded fixed-size local schema beyond the structural decoder, including selected compound, string, enum, bitfield, reduced-precision, and remapped local reference cases; linked-library NBIT, SCALEOFFSET, and SZIP are available when their decoders are installed. This route cannot prove historical values or repair an inaccessible index. Variable-length graphs, arbitrary plugins, and external reference targets remain refused. An explicit large native-readable route streams only one-dimensional primitive numeric selected data under a 64 GiB physical-source, 8 GiB copied-snapshot, 16 GiB logical and other quota ceilings. Its sparse validity and physical evidence arrays are stored in output HDF5 rather than a giant JSON report. Ordinary structural limits remain smaller. Native and structural routes in guided rescue run in deadline-bound children with dynamic plugins disabled; POSIX has a 3 GiB address-space cap, while Windows has no enforced child memory cap. This is crash and resource isolation, not a security sandbox.

Four unchanged scientific originals are bundled. Six of 251 inventoried datasets are chunked structural candidates, and their intact exports matched 196/196 independently checked chunks. A controlled GWOSC broken-pointer copy recovered 128/128 exact chunks, including 57 behind the justified leaf bridge. A separate optional-metadata fault on a GWOSC numeric dataset exercised older rooted fallback. Two intact Zenodo datasets passed native-readable comparison. Generated positive and adversarial fixtures exercise the new routes. The held-out panel runner measures planned, eligible and excluded fault/file pairs, wrong accepted values and refusals, but the bundled files are development calibration. None of these results measures a representative population of damaged scientific files or establishes a 50% or 99% field success rate. The healthy originals are used for controlled damage generation and independent scoring; recovery receives the damaged copy alone. See [status](status.md) for the exact current verification record.

## Format coverage and damage recovery are different

**Format support** asks whether a parser or bounded native route understands this file's actual superblock, object header, datatype, layout, index, filters, and file driver. **Damage recoverability** asks whether enough correct bytes and independent positional evidence survived to establish the original measurements. An intact index parser does not automatically repair that index when its critical pointer is gone. A current file hash establishes the identity of the supplied bytes, not their pre-damage truth.

| Representation | Implemented route and evidence | Important remaining failure |
| --- | --- | --- |
| Compact and contiguous | Rooted structural numeric export for selected layout v3–v5; readable fixed-size values through native HDF5 | Destroyed compact header/payload; absent layout address; ambiguous ownership; incomplete or overwritten element bytes |
| Version-1 chunk B-tree | Intact deeper trees and one uniquely anchored missing leaf link | Missing internal subtree, multiple detached leaves, stale but internally plausible ownership |
| Five modern chunk indexes | Intact bounded single, implicit, fixed, extensible, and version-2 tree variants; paged fixed and extensible arrays included. Selected broken links need unique original-checksum substitution, checked child and full traversal | Other broken pointer positions, checksum-field or multi-byte damage, ambiguous detached blocks, unknown allocation history |
| Physically cut chunked tail | Fully present rooted path, index and stored chunks before actual EOF; cut indexed payloads unknown | Cut selected metadata, cut index, declared-minus-physical EOF over 256 MiB, missing original bytes |
| External raw, VDS, and external link | Explicit pinned local sources; bounded segment or finite regular mapping, or one local hard-link target reached across a pinned external link | Damaged mapping metadata, dynamic names, recursive/transitive links, unsupported selections, absent source bytes |
| Family and Split drivers | Hash-pinned Family member set or checked two-member Split map; native-readable selected values | Other Multi/Subfiling layouts, missing metadata member, holes without justified assignment |
| Independent replicas and parity | Matching prior coordinate hashes; one missing chunk per retained XOR stripe, or up to 2 to 4 per stripe with pre-incident GF(256) shards | No trustworthy pre-damage capture, too many losses per stripe, conflicting copies, missing selected schema |
| Prospective schema/physical capsule | Separate pre-incident exact selected HDF5 schema and chunk-range/hash map can bypass root, header or index loss; matching unfiltered blocks retain partial element validity | No trustworthy independent capture; changed filtered stream, moved payload, missing unique bytes, or capture bounds |
| Prior hash gates | Compact/contiguous stored-element or chunked decoded-coordinate comparison against separately retained prospective baseline | A post-damage baseline, replaced baseline, destroyed unique bytes, or lost selected schema |
| Status flag | Checked v3 flag and checksum trial on a disposable copy, then bounded native-readable export | Write did not finish; other damage, bad original checksum, or EOA beyond EOF |
| Checked modern metadata trial | Original-checksum-constrained single-byte root/layout pointer correction and bounded native-readable export on disposable copy | Unsupported parent graph, changed checksum field, multiple errors, or no unique matching substitution |
| Large readable selected values | One-dimensional primitive numeric native streaming with physical evidence and sparse validity inside output HDF5 | Inaccessible index, unsupported schema or rank, resource quota, and unverified historical values |
| Fixed chunked records | Exact HDF5 file type encoding and raw chunk bytes for bounded compound, enum, array, fixed string and opaque types | Variable-length, heap-backed or reference graphs and unsupported nested type semantics |

The [HDF5 format specification](https://support.hdfgroup.org/documentation/hdf5/latest/_f_m_t4.html) describes the format variants; the [dataset storage guide](https://support.hdfgroup.org/documentation/hdf5/latest/_l_b_dset_layout.html) describes their layout choices. Actual version fields and messages, rather than a filename or familiar scientific schema, select a parser. An unknown dataset must not be converted silently into a known layout: shape, type, filters, axis meaning, and dependencies can change the measurement's meaning.

## Evidence and publication rules

1. **Freeze the inputs.** The primary source is copied to a stable bounded snapshot, checked for changes, and never modified. Related files need explicit names and hashes; dependent routes check private snapshots and physical ranges. The ordinary source default is 4 GiB; explicit large native streaming raises this under separate sparse-copy and disk quotas. Smaller element, chunk, decoder, report, and worker limits also apply. A group of independently captured files is not automatically an atomic acquisition snapshot.
2. **Choose an evidence route.** A surviving selected root path and metadata define the dataset. Raw signatures, convenient shapes, user hints, and high-looking scores only identify candidates. File drivers and dependencies need their own mapping rules. A checked status flag can warrant a disposable status-only trial or optional `h5clear --status` inspection, but [h5clear is not a general repair tool](https://support.hdfgroup.org/documentation/hdf5/latest/_h5_t_o_o_l__c_r__u_g.html).
3. **Reconcile ownership and bytes.** Record every accepted chunk or element's coordinate, physical source, link chain, allocation state, filters, checksums, and contradictions. Enforce bounds and no contradictory physical reuse. Positive sibling allocations can reject a redirected candidate, but a damaged or incomplete object graph can hide other owners. A checksum may detect changed bytes; its absence cannot certify historical authenticity, and a checksum that itself was recomputed is not independent truth.
4. **Publish uncertainty.** Accepted regions have a validity or status map and evidence report. Fill in an unknown position never counts as a recovered measurement. Missing decoders and corrupt streams have separate outcomes. Bounded anchored raw fragments may be exported without claiming a scientific coordinate. Reports disclose schema and metadata omissions. A failed or incomplete publication must not be mistaken for a completed recovery.

The [filter guide](https://support.hdfgroup.org/documentation/hdf5/latest/_h5_z__u_g.html) documents built-in and custom filters. Correct decoding depends on order, parameters, and per-chunk skip masks. Arbitrary executable plugins are not loaded by default. The [dataset API](https://support.hdfgroup.org/documentation/hdf5/latest/group___h5_d.html) can expose chunk addresses and masks for intact indexes; it is useful for independent checks on controlled originals, not a substitute for structural reasoning when the index is damaged.

## Scientist input and next implementation gates

Guided inspection can accept a selected dataset path and optional independently known schema, axis order, chunk shape, filter settings, instrument/software version, run logs, related files, sample checksums, or pre-acquisition sidecars. Such a hint narrows investigation but cannot prove which surviving compressed block belongs at a time coordinate. If two assignments remain possible, both are ambiguous. Scientists should see which assertions came from damaged metadata, which from their supplied evidence, and which are only inferences.

| Next gate | Concrete work and condition for support |
| --- | --- |
| More structural formats | Add remaining older layout/header variants, deeper and mixed shared-message heap/index variants, and other damaged modern links only where independent anchors establish exact parent and coordinate; differential positive and deliberately misleading negative cases for each variant |
| Broader representations | Extend bounded structural types beyond current self-contained fixed records to selected variable-length/reference graphs, noncanonical numeric fields and additional filters only when heap/object ownership and type semantics can be independently verified |
| More dependencies | Add other VFD maps, virtual selection forms, transitive dependencies, and atomic bundle capture; refuse conflicting source identity, overlap, or missing bytes rather than accepting native fill |
| Payload redundancy | Exercise current XOR and GF(256) sidecars and capsule block granularity on independent scientific acquisitions; add stronger acquisition-specific redundancy where available, reject stale/replaced sidecars, and quantify loss tolerance; hashes by themselves detect but do not replace bytes |
| Field validation | Obtain consented naturally damaged, blinded cases from multiple producers with acquisition histories and independent truth where possible; audit false accepts, refusals, resource use, and provenance |

This table is a work list, not a claim that every damaged instance of a newly parsed format will become recoverable. Corrupt unique payload bytes need redundancy or another copy. A missing index with no surviving ownership anchors can make multiple coordinate assignments equally consistent.

## Measuring coverage honestly

Keep a pinned corpus of unchanged files from different producers, HDF5 versions, datatypes, filters, storage layouts, dimensions, drivers, and dependencies. Inventory unsupported cases too. In separate disposable copies, inject documented bit flips, burst writes, broken links and pointers, checksum contradictions, partial truncation, status flags, stale or redirected allocations, missing dependent files, and combinations. Vary the location and magnitude within each fault class using published seeds and mutation manifests. Include held-out cases the implementation was not tuned against and naturally damaged files when owners permit analysis. A naturally damaged file without trustworthy truth cannot establish an exact-value score.

Report format support by stratum, denominator and sampling method, correct coordinates and bit-exact values, unknown regions, falsely accepted values, refusals, time and memory, original preservation, and version regressions. Distinguish currently readable export, structurally justified recovery, independent checksum confirmation, and exact independent reference comparison. Generated fixtures and hundreds of mutations of the same known pointer pattern cannot estimate general recovery coverage.

**“50%” or “99%” requires a specified population and outcome.** It could describe supported files in a declared population, recoverable chunks under a stated fault distribution, or exact values from cases with independent truth. Those are different rates. Publish inclusion criteria, sample selection, fault distribution, uncertainty interval, exactness threshold, unsupported/refused cases, and false-accept rate, with a held-out multi-lab evaluation. No current result supports either claim across HDF5 damage causes.

If the only copy of bytes was overwritten, their original values cannot be derived from that file alone. If both an index and every corroborating ownership/coordinate anchor are lost, a decodable payload may still have no justifiable position. Checksums cannot recreate rejected bytes; lossy filters may already have discarded precision. [External raw storage](https://support.hdfgroup.org/documentation/hdf5/latest/group___d_c_p_l.html) and [virtual datasets](https://support.hdfgroup.org/documentation/hdf5/latest/rel_spec_110.html) can fail because another file vanished. In these cases, partial output with explicit unknowns, an unassigned fragment, or refusal is the correct result. Universal exact repair of arbitrary damaged HDF5 files from the damaged file alone is impossible.
