# Generalization plan and limits

H5Reclaim tries to recover measurements that remain physically present in damaged HDF5 storage, assign them only to coordinates justified by surviving evidence, and mark everything else unknown. This document records what version 0.7 implements and the remaining engineering and evaluation work. The [current status](status.md) and [usage guide](usage.md) describe the commands and their narrower conditions.

## What works in version 0.7

The guided rescue command selects one local dataset and publishes a separate derived HDF5 file with an evidence report and validity or status map. The chunked structural route supports selected older and newer superblocks, object headers, groups and hard-link paths. It follows intact deeper version-1 B-trees and can bridge **one missing leaf link** only when a unique two-sided sibling chain and the parent's exact interval agree. It validates intact single-chunk, implicit, fixed-array, extensible-array (including bounded paged blocks), and version-2 B-tree modern indexes. It does **not** infer a missing modern index link or accept an orphan found by scanning. Bounded fallback can resolve selected old symbol-table, modern compact, and dense-group paths when native metadata open fails. Selected checksummed v2 committed datatypes and SOHM record-list/managed-heap shared dataspace, datatype, and filter messages are supported; other shared-message encodings remain unsupported. Observed allocations of other rooted local datasets can contradict a proposed chunk range. An incomplete native sibling inventory is reported as incomplete and is not proof that no competitor exists.

Structural chunked values are rank-one through rank-four canonical fixed-width integers or IEEE float32/64, with supported built-in shuffle, DEFLATE, and Fletcher32 pipelines in declared order and per-chunk skip masks. The route handles edge chunks, growth, and sparse slots within limits. The evidence ledger records anchors, index paths, coordinates, byte extents, hashes, filter checks, and contradictions. An accepted unchecksummed chunk is structurally located, but its current bits are not independently proven to be the pre-damage measurement. Missing, ambiguous, undecodable, and unsupported regions remain distinct; anchored undecodable raw extents can be exported as **unassigned** fragments.

A separate rooted structural route accepts selected compact and contiguous numeric datasets, rank zero through four, with layout messages v3–v5. It retains only complete elements from a physically truncated contiguous tail and marks incomplete or absent elements unknown. It uses a surviving hard-link path, datatype, dataspace, layout, and address; it does not search the file for plausible numbers. The older unchecksummed metadata route has a weaker ownership guarantee than a checked modern header. A positively observed competing rooted allocation causes refusal.

Related-file routes use explicit manifests, pinned hashes, private snapshots, and checked physical extents. External raw export maps complete elements through declared segments; it refuses an unverified supplied file and marks physically absent element bytes unknown. Finite virtual datasets map supported ALL or regular hyperslab selections to supplied local native-readable numeric sources. Missing VDS sources and unallocated source coordinates remain unknown, even where native HDF5 would show fill. Family and two-member Split driver routes validate their supplied member layout before native-readable export. These routes materialize a local selected dataset and do not reproduce the original cross-file configuration.

The capture-baseline and optional capture-parity commands are **prospective** tools to run while an acquisition is intact. Baseline hashes identify decoded chunks at exact coordinates; pinned independent HDF5 replicas can supply matching chunks later. The XOR parity sidecar can reconstruct exactly one unknown chunk per stripe when all surviving companions and the result match the prior baseline. Neither route creates a trustworthy prior checksum after damage or restores two missing chunks from one parity stripe.

The native-readable route is separately labeled: it copies values that the linked HDF5 library can currently read. It supports bounded fixed-size local schema beyond the structural decoder, including selected compound, string, enum, bitfield, reduced-precision, and remapped local reference cases; linked-library NBIT, SCALEOFFSET, and SZIP are available when their decoders are installed. This route cannot prove historical values or repair an inaccessible index. Variable-length graphs, arbitrary plugins, and external reference targets remain refused. Native operations in guided rescue run in a child with a deadline and disabled dynamic plugins; POSIX has a 3 GiB address-space cap, while Windows has no enforced child memory cap. This is crash and resource isolation, not a security sandbox.

Four unchanged scientific originals are bundled. Six of 251 inventoried datasets are chunked structural candidates, and their intact exports matched 196/196 independently checked chunks. A controlled GWOSC broken-pointer copy recovered 128/128 exact chunks, including 57 behind the justified leaf bridge. Two intact Zenodo datasets passed native-readable comparison. Generated positive and adversarial fixtures exercise the additional routes. None of these results measures a general population of damaged scientific files or establishes a 99% field success rate. The healthy originals are used for controlled damage generation and independent scoring; the recovery command receives the damaged copy alone. See [status](status.md) for the exact current verification record.

## Format coverage and damage recovery are different

**Format support** asks whether a parser or bounded native route understands this file's actual superblock, object header, datatype, layout, index, filters, and file driver. **Damage recoverability** asks whether enough correct bytes and independent positional evidence survived to establish the original measurements. An intact index parser does not automatically repair that index when its critical pointer is gone. A current file hash establishes the identity of the supplied bytes, not their pre-damage truth.

| Representation | Implemented route and evidence | Important remaining failure |
| --- | --- | --- |
| Compact and contiguous | Rooted structural numeric export for selected layout v3–v5; readable fixed-size values through native HDF5 | Destroyed compact header/payload; absent layout address; ambiguous ownership; incomplete or overwritten element bytes |
| Version-1 chunk B-tree | Intact deeper trees and one uniquely anchored missing leaf link | Missing internal subtree, multiple detached leaves, stale but internally plausible ownership |
| Five modern chunk indexes | Intact bounded single, implicit, fixed, extensible, and version-2 tree variants; paged fixed and extensible arrays included | Broken parent/index pointers, ambiguous detached blocks, unknown allocation history |
| External raw and VDS | Explicit pinned local sources; bounded segment or finite regular mapping; unknown map for missing bytes | Damaged mapping metadata, dynamic names, transitive sources, unsupported selections, absent source bytes |
| Family and Split drivers | Hash-pinned Family member set or checked two-member Split map; native-readable selected values | Other Multi/Subfiling layouts, missing metadata member, holes without justified assignment |
| Independent replicas and parity | Matching prior coordinate hashes; one missing chunk per retained XOR stripe | No trustworthy pre-damage capture, two losses per stripe, conflicting copies, missing selected schema |

The [HDF5 format specification](https://support.hdfgroup.org/documentation/hdf5/latest/_f_m_t4.html) describes the format variants; the [dataset storage guide](https://support.hdfgroup.org/documentation/hdf5/latest/_l_b_dset_layout.html) describes their layout choices. Actual version fields and messages, rather than a filename or familiar scientific schema, select a parser. An unknown dataset must not be converted silently into a known layout: shape, type, filters, axis meaning, and dependencies can change the measurement's meaning.

## Evidence and publication rules

1. **Freeze the inputs.** The primary source is copied to a stable bounded snapshot, checked for changes, and never modified. Related files need explicit names and hashes; dependent routes check private snapshots and physical ranges. The current source default is 4 GiB and smaller element, chunk, decoder, report, and worker limits also apply. A group of independently captured files is not automatically an atomic acquisition snapshot.
2. **Choose an evidence route.** A surviving selected root path and metadata define the dataset. Raw signatures, convenient shapes, user hints, and high-looking scores only identify candidates. File drivers and dependencies need their own mapping rules. A status flag can warrant h5clear --status inspection on a disposable copy, but [h5clear is not a general repair tool](https://support.hdfgroup.org/documentation/hdf5/latest/_h5_t_o_o_l__c_r__u_g.html).
3. **Reconcile ownership and bytes.** Record every accepted chunk or element's coordinate, physical source, link chain, allocation state, filters, checksums, and contradictions. Enforce bounds and no contradictory physical reuse. Positive sibling allocations can reject a redirected candidate, but a damaged or incomplete object graph can hide other owners. A checksum may detect changed bytes; its absence cannot certify historical authenticity, and a checksum that itself was recomputed is not independent truth.
4. **Publish uncertainty.** Accepted regions have a validity or status map and evidence report. Fill in an unknown position never counts as a recovered measurement. Missing decoders and corrupt streams have separate outcomes. Bounded anchored raw fragments may be exported without claiming a scientific coordinate. Reports disclose schema and metadata omissions. A failed or incomplete publication must not be mistaken for a completed recovery.

The [filter guide](https://support.hdfgroup.org/documentation/hdf5/latest/_h5_z__u_g.html) documents built-in and custom filters. Correct decoding depends on order, parameters, and per-chunk skip masks. Arbitrary executable plugins are not loaded by default. The [dataset API](https://support.hdfgroup.org/documentation/hdf5/latest/group___h5_d.html) can expose chunk addresses and masks for intact indexes; it is useful for independent checks on controlled originals, not a substitute for structural reasoning when the index is damaged.

## Scientist input and next implementation gates

Guided inspection can accept a selected dataset path and optional independently known schema, axis order, chunk shape, filter settings, instrument/software version, run logs, related files, sample checksums, or pre-acquisition sidecars. Such a hint narrows investigation but cannot prove which surviving compressed block belongs at a time coordinate. If two assignments remain possible, both are ambiguous. Scientists should see which assertions came from damaged metadata, which from their supplied evidence, and which are only inferences.

| Next gate | Concrete work and condition for support |
| --- | --- |
| More structural formats | Add older layout/header variants, additional shared-message heaps and indexes, damaged modern links only where independent anchors establish exact parent and coordinate; differential positive and deliberately misleading negative cases for each variant |
| Broader representations | Extend bounded structural type decoders and schema preservation for compound, strings, variable-length/reference graphs, noncanonical numeric fields, and additional filters; verify type semantics and safety with independent readers |
| More dependencies | Add other VFD maps, virtual selection forms, transitive dependencies, and atomic bundle capture; refuse conflicting source identity, overlap, or missing bytes rather than accepting native fill |
| Payload redundancy | Add independently trustworthy sidecars or acquisition-specific redundancy strategies where available; quantify loss tolerance and reject stale or forged sidecars |
| Field validation | Obtain consented naturally damaged, blinded cases from multiple producers with acquisition histories and independent truth where possible; audit false accepts, refusals, resource use, and provenance |

This table is a work list, not a claim that every damaged instance of a newly parsed format will become recoverable. Corrupt unique payload bytes need redundancy or another copy. A missing index with no surviving ownership anchors can make multiple coordinate assignments equally consistent.

## Measuring coverage honestly

Keep a pinned corpus of unchanged files from different producers, HDF5 versions, datatypes, filters, storage layouts, dimensions, drivers, and dependencies. Inventory unsupported cases too. In separate disposable copies, inject documented bit flips, burst writes, broken links and pointers, checksum contradictions, partial truncation, status flags, stale or redirected allocations, missing dependent files, and combinations. Vary the location and magnitude within each fault class using published seeds and mutation manifests. Include held-out cases the implementation was not tuned against and naturally damaged files when owners permit analysis. A naturally damaged file without trustworthy truth cannot establish an exact-value score.

Report format support by stratum, denominator and sampling method, correct coordinates and bit-exact values, unknown regions, falsely accepted values, refusals, time and memory, original preservation, and version regressions. Distinguish currently readable export, structurally justified recovery, independent checksum confirmation, and exact independent reference comparison. Generated fixtures and hundreds of mutations of the same known pointer pattern cannot estimate general recovery coverage.

**“99%” requires a specified population and outcome.** It could describe supported files in a declared population, recoverable chunks under a stated fault distribution, or exact values from cases with independent truth. Those are different rates. Publish inclusion criteria, sample selection, fault distribution, uncertainty interval, exactness threshold, unsupported/refused cases, and false-accept rate, with a held-out multi-lab evaluation. No current result supports a 99% claim across HDF5 damage causes.

If the only copy of bytes was overwritten, their original values cannot be derived from that file alone. If both an index and every corroborating ownership/coordinate anchor are lost, a decodable payload may still have no justifiable position. Checksums cannot recreate rejected bytes; lossy filters may already have discarded precision. [External raw storage](https://support.hdfgroup.org/documentation/hdf5/latest/group___d_c_p_l.html) and [virtual datasets](https://support.hdfgroup.org/documentation/hdf5/latest/rel_spec_110.html) can fail because another file vanished. In these cases, partial output with explicit unknowns, an unassigned fragment, or refusal is the correct result. Universal exact repair of arbitrary damaged HDF5 files from the damaged file alone is impossible.
