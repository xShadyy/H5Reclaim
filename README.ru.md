H5Reclaim восстанавливает научные данные из повреждённых файлов HDF5. После прерванной записи, нарушения индексов, повреждения метаданных или усечения файла программа переносит уцелевшие измерения в новый пригодный для работы файл. Формат HDF5 используется многими научными приборами и приложениями для хранения массивов, измерений и их метаданных.

**Одна команда находит наборы данных, выбирает способы восстановления и создаёт новый файл HDF5 с понятным отчётом в формате JSON.** Исходный файл остаётся неизменным. H5Reclaim сохраняет читаемые измерения из частично повреждённых наборов данных и продолжает восстанавливать остальную часть файла.

Кандидат в релизы 1.0.0rc1 обеспечил **полезное восстановление в 95,4% из 109 контролируемых испытаний с повреждёнными файлами**: 77 полностью точных и 27 частичных восстановлений без ошибочно принятых значений в этой серии испытаний. Эти сгенерированные испытания проверяют заявленные классы повреждений, а не ожидаемую вероятность успеха для других файлов. [Изучить результаты](docs/coverage.md).

## Начало работы

Требуется Python 3.10 или новее. Клонируйте репозиторий либо скачайте и распакуйте его ZIP-архив с GitHub:

```sh
git clone https://github.com/xShadyy/H5Reclaim.git
cd H5Reclaim
python -m venv .venv
```

Активируйте окружение:

| Система | Команда |
| --- | --- |
| Windows PowerShell | `.venv\Scripts\Activate.ps1` |
| Windows Command Prompt | `.venv\Scripts\activate.bat` |
| macOS / Linux | `. .venv/bin/activate` |

Установите программу из корневого каталога репозитория и восстановите файл:

```sh
python -m pip install .
python -m h5reclaim rescue "damaged.h5"
```

Рядом с исходным файлом будут созданы `damaged.recovered.h5` и `damaged.recovered.report.json`. Существующие файлы назначения никогда не перезаписываются. Чтобы выбрать другое место или повторить запуск, укажите пути явно:

```sh
python -m h5reclaim rescue "damaged.h5" --output "rescued.h5" --report "evidence.json"
```

Установленная команда `h5reclaim` также работает. Запустите `python -m h5reclaim --help`, чтобы посмотреть команды, или `python -m h5reclaim rescue --help`, чтобы узнать параметры восстановления.

## Как понимать результат

Сводка в терминале показывает, было ли восстановление полным или частичным, и указывает расположение выходных файлов. В отчёте JSON перечислены восстановленные наборы данных, применённые методы, неразрешённые позиции и восстановленные метаданные.

Перед использованием выходного файла проверьте его по сохранённому отчёту:

```sh
python -m h5reclaim verify-result "damaged.recovered.h5" "damaged.recovered.report.json" --source "damaged.h5"
```

Проверка выполняется в процессе с ограничением ресурсов и сопоставляет отчёт, форму наборов данных, хеш исходного файла и согласованность карты достоверности. Она не считывает и не подтверждает подлинность восстановленных значений измерений; для методов без проверяемой карты возвращается результат «не поддерживается». Коды завершения и ограничения приведены в [руководстве](docs/usage.md#verify-a-published-result).

Если метод создаёт **карту состояний**, она показывает позиции, содержащие принятые измерения. Для анализа выбирайте значения по карте, указанной в отчёте; неизвестные позиции могут отображаться как заполнитель, например ноль. Для некоторых неповреждённых непрерывных наборов данных и наборов данных типа null проверяемая карта отсутствует, поэтому перед анализом ознакомьтесь с отчётом для соответствующего метода. Ранее сохранённые базовые копии и комплекты защиты позволяют сопоставить результат с более ранним снимком данных.

Для наборов данных фиксированного размера можно прочитать восстановленные значения, уже замаскировав неизвестные позиции:

```python
from h5reclaim import read_masked

values = read_masked(
    "damaged.recovered.h5", "damaged.recovered.report.json",
    "/experiment/readings", selection=(slice(0, 1000), Ellipsis),
)
```

Этот считыватель с ограничением ресурсов использует карту состояний набора данных, указанную в отчёте. Маска обозначает значения, принятые из повреждённого входного файла; она не доказывает, что они совпадают с более ранним снимком. Поддерживаемые выборки и ограничения описаны в [руководстве](docs/usage.md#read-results).

## Типовые задачи

| Задача | Команда |
| --- | --- |
| Проверить файл перед восстановлением | `python -m h5reclaim diagnose damaged.h5` |
| Восстановить один набор данных | `python -m h5reclaim rescue damaged.h5 --dataset /experiment/readings` |
| Просмотреть сводку готового результата | `python -m h5reclaim report damaged.recovered.report.json` |
| Проверить согласованность выходного файла и отчёта | `python -m h5reclaim verify-result damaged.recovered.h5 damaged.recovered.report.json` |
| Продолжить длительное восстановление | `python -m h5reclaim rescue damaged.h5 --resume-dir recovery-progress` |
| Передать сопутствующие файлы | `python -m h5reclaim rescue container.h5 --related-dir companion-files` |
| Найти наборы данных после утраты их имён | `python -m h5reclaim discover damaged.h5 --json` |

Для некоторых файлов требуются дополнительные кодеки сжатия. Установите их командой `python -m pip install ".[filters]"` из корневого каталога репозитория и повторите попытку. В [руководстве](docs/usage.md) описаны большие файлы, ограничения ресурсов, зависимые файлы, возобновляемые запуски и ранее созданные комплекты защиты.

## Возможности восстановления

H5Reclaim читает описания наборов данных из самого файла, поэтому один и тот же порядок работы подходит для разных экспериментов, имён наборов данных и форм массивов.

| Область | Реализованные возможности |
| --- | --- |
| Хранение | Компактные, непрерывные и разбитые на блоки наборы данных; прежние и современные индексы блоков |
| Значения | Числовые массивы, составные записи, строки фиксированной и переменной длины, массивы переменной длины, перечисления, ссылки, пустые и null-наборы данных |
| Повреждения | Восстановление разорванных связей индекса, исправления метаданных и размерностей блоков с подтверждением контрольными суммами, исправление современных сигнатур, флаги прерванной записи, уцелевшие заголовки наборов данных, нечитаемые блоки и физическое усечение конца файла |
| Сжатие | DEFLATE, LZF, shuffle, Fletcher32 и поддерживаемые дополнительные кодеки из пакетов |
| Структура файла | Доступные группы, атрибуты, связи, именованные типы данных, ссылки, шкалы измерений и заголовки приложений |
| Зависимости | Внешнее хранилище, виртуальные наборы данных, внешние связи и файлы Family/Split при явном указании сопутствующих файлов или манифестов |

Если данные были защищены до повреждения, сохранённые реплики и блоки чётности также могут помочь восстановить недостающие данные. Поиск сопутствующих файлов, возобновляемое восстановление и ограничение ресурсов при потоковой обработке помогают работать с более крупными научными данными.

**Тест автоматического восстановления версии 1.0.0rc1** охватывает 23 сгенерированных семейства данных и вариантов размещения. В **109 контролируемых испытаниях с повреждёнными файлами** получено 77 полностью точных восстановлений, 27 частичных и 5 отказов: **104 полезных результата (95,4%)**. В точных координатах восстановлено 83,1% исходных элементов, без ошибочно принятых значений и без изменений исходных файлов. Все 15 заявленных случаев повреждения размерностей блоков дали полезный результат, включая пятимерные массивы, scale-offset, строки переменной длины, массивы переменной длины и составные поля переменной длины. [Полный отчёт по испытаниям](benchmarks/results/v100rc1-release-coverage.json) и [разбор покрытия](docs/coverage.md).

Среди зарегистрированных проверок версии v0.14.0:

| Проверка | Зарегистрированный результат |
| --- | --- |
| [Четыре неповреждённых научных файла](benchmarks/results/v014-scientific-whole.json) | 251 набор данных и 253 атрибута точно совпали с сохранёнными оригиналами |
| [Контролируемое повреждение связи индекса GWOSC](benchmarks/results/v014-gwosc-controlled.json) | 128/128 блоков восстановлены в точных координатах; ни одного ошибочного блока |
| [MATLAB 7.3, netCDF4 и NWB](benchmarks/results/v014-application-readers.json) | Независимые программы чтения открыли шесть результатов для неповреждённых файлов или файлов с контролируемыми повреждениями; ни одного ошибочно принятого элемента, повреждённые области оставлены неизвестными |

В [руководстве по тестам](benchmarks/README.md) объясняется, как воспроизвести проверки. [Примечания к набору файлов](corpus/README.md) содержат сведения об источниках научных файлов.

## Участие в разработке и сообщения о проблемах

Создайте [сообщение о проблеме](https://github.com/xShadyy/H5Reclaim/issues), указав команду, версии инструмента и Python, наблюдаемую ошибку и ожидаемый результат. Небольшой файл, воспроизводящий проблему, и отчёт помогут отличить неподдерживаемый способ хранения от ошибки восстановления.

О найденной уязвимости сообщайте согласно [правилам безопасности](SECURITY.md); перед публикацией отчётов проверьте, нет ли в них конфиденциальных путей и метаданных.

Для разработки установите `python -m pip install -e ".[filters]"` и запустите:

```sh
python -m unittest discover -s tests -q
```

Тесты проверяют правильность восстановления, сохранность исходного файла и обработку неразрешённых данных. Тестовые сценарии сравнивают принятые значения с отдельно сохранёнными оригиналами. [Путеводитель по репозиторию](docs/file-guide.md) показывает расположение компонентов и объясняет назначение файлов.
В [инструкции по выпуску](docs/releasing.md) описаны сборка кандидата в релизы, проверка тега и оставшиеся проверки для стабильной версии 1.0.
